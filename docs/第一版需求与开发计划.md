# 个人贡献证据关联与验收系统第一版

本项目用于学生团队课程项目：学生说明本人完成的工作，把证据定位到具体任务标准，教师依据材料确认贡献并给出验收结论。本版为可运行的毕业设计起点，需求来自本次讨论；尚未收到学校任务书或论文模板。

## 角色和权限

教师创建项目、选择成员、发布任务及验收标准，审核自己项目中的学生申报，查看这些项目的个人报告。

学生查看自己参加的项目和任务，在分配给自己的任务下提交个人贡献；可引用同项目的已有证据，也可上传新材料。第一版每项任务有一名负责人，多人合作时拆分任务，各自说明对共同材料的贡献。学生只能补交自己的被退回申报，不能代替他人提交或验收。

## 第一版业务流程

1. 教师创建项目并选择学生成员。
2. 教师创建任务、分配负责人、填写截止日期及可检查的验收标准。
3. 学生填写本人完成的工作，上传文件或添加链接。
4. 每个证据引用指定一项任务标准，填写证据位置和证明内容。
5. 教师查看最新提交的材料，对引用的标准逐项验收。
6. 全部引用标准通过后，确认本次贡献；材料不足时，写明意见并退回。
7. 学生补交生成新修订，原始说明、证据引用及旧验收意见保留。
8. 个人报告展示申报状态、已确认贡献、证据和验收记录，可导出 CSV 或打印。

本版的“通过”表示该次个人贡献申报经教师确认，不自动等价于整个团队项目已经验收完成。任务的全部标准可能由不同申报分别支持。

## 关联和历史规则

贡献申报属于一个学生和一个任务；每次提交生成一个不可变修订。证据是不可变的材料记录，替换文件时创建新记录；引用关系连接修订、证据和任务标准。

证据上传者不等于全部贡献的所有者。同一项目成员可在不同申报中引用同一材料，但需要填写各自工作内容。引用次数、文件数量、代码行数均不自动折算贡献分数。

教师验收绑定确切的修订 ID。已验收版本不得再写入另一条竞争结论，旧版本不得替代新版本验收。第一版不开放已发布任务标准的编辑，以保证旧记录含义稳定；标准版本管理作为后续迭代。

## 技术结构

- 前端：Vue 3、Vue Router、Vite，使用哈希路由。
- 后端：Java 21、Spring Boot、JdbcTemplate、分层 REST API。
- 本地数据库：H2 文件模式。数据存入磁盘，重启保留业务数据。
- 附件：本地目录，数据库保存原名、存储名和 SHA-256。哈希用于核对内容完整性，不用于证明作者身份。
- 登录：密码加盐哈希，随机令牌验证身份。退出令牌失效；重启后需要重新登录。
- 交付方式：前端构建文件打包进后端 JAR，使用一个本地服务运行。

## 页面

登录、项目总览、任务与标准、贡献申报及详情、教师验收工作台、个人报告。项目和任务创建、证据上传与关联通过表单完成。

首屏统计来自当前身份可访问的实际数据。系统提供一个演示项目、三个学生账户与三种申报状态，方便理解流程；可通过真实接口创建自己的项目。

## 验证重点

- 正确登录、错误密码拒绝、未登录请求拒绝。
- 学生不能创建教师任务、替他人申报或自行验收。
- 项目之间不能越权引用证据或下载材料。
- 验收标准必须属于申报对应的任务。
- 退回补交后仍能查看旧版本和旧意见。
- 已通过记录不会被待验收修订覆盖或虚增统计。
- 重复验收和过期版本验收被拒绝。
- 刷新页面、重启服务后数据仍在。
- 桌面及手机宽度下内容可读，主要流程可操作。
